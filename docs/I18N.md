# Language system design

The game UI supports three locales: English (`en`), Simplified Chinese (`zh-CN`) and Traditional Chinese (`zh-TW`). This note covers what is translated, where each string comes from, and how the locale reaches every part of the board.

## Scope

Translated:

- HUD text: phase, buttons, status messages, drop hints, tooltips, choice panels, roster summaries, combat results.
- Accessible names: `aria-label`, `aria-description` and `title`.
- Card names and rules text, including hero powers, trinkets, Dark Gifts and other attached cards.
- Scenario names in the menu.
- Text drawn into the 3D scene: the spell label on card faces, the fallback emblem glyph and the combat "blocked" burst.

Not translated:

- Engine data used as identifiers: race codes, keyword flags and card IDs.
- Backend error codes. The frontend shows its own text for each code.
- Developer documentation and logs.

## Locale

```ts
type Locale = 'en' | 'zh-CN' | 'zh-TW';
```

The locale is chosen in this order:

1. The `?lang=` query parameter.
2. The player's last choice, saved in `localStorage` (`locale`).
3. `navigator.languages`:
   - `zh-TW`, `zh-HK`, `zh-MO` and any `zh-Hant*` tag map to `zh-TW`.
   - Any other `zh*` tag maps to `zh-CN`.
   - Anything else maps to `en`.
4. `en`.

A language menu sits next to the scenario menu. Changing it saves the choice, sets `<html lang>` and redraws the HUD and the card faces from the current snapshot. The game is not restarted.

`localStorage` is a convenience only. Every read and write is wrapped so that a blocked or empty store falls back to the browser language.

## UI catalogs

Files:

- `frontend/src/i18n/index.ts`: the locale state, `t()` and the card text helpers.
- `frontend/src/i18n/zh-CN.ts`: the source catalog.
- `frontend/src/i18n/en.ts` and `frontend/src/i18n/zh-TW.ts`: the translations.

Each catalog is a plain nested object of strings and functions:

```ts
export const zhCN = {
  phase: { recruit: (turn: number) => `招募 · 第 ${turn} 回合` },
  tools: { refresh: (price: number) => `⟳ 刷新 ${price}` },
} as const;
export type Messages = typeof zhCN; // shape only; see below
```

Rules:

- `Messages` is derived from the zh-CN catalog, because zh-CN is the current UI text. `en` and `zh-TW` are declared as `Messages`, so a missing or misspelled key fails type checking.
- **Interpolation:** messages that take values are functions. Word order, plurals ("1 minion" and "2 minions") and spacing differ per language, so templates live in each catalog rather than in code that concatenates fragments.
- **No runtime library:** the catalogs are small enough that typed objects are simpler than a message-format dependency.
- **Lookups:** code reads `t().phase.recruit(turn)`. `t()` returns the current catalog, so the next render after a switch uses the new language.

## Card names and text

| Locale | Name | Text |
| --- | --- | --- |
| `en` | `name` | `text` |
| `zh-CN` | `name_zh` | `text_zh` |
| `zh-TW` | `name_tw` | `text_tw` |

- **Source fields:** the engine catalog carries enUS (`name`, `text`) and zhCN (`name_zh`, `text_zh`). It has no zhTW strings.
- **Traditional fields:** the backend converts the zhCN strings with OpenCC (`s2twp`: Taiwan characters and common Taiwan phrasing). It adds `name_tw` and `text_tw` to every card object it sends. Results are cached per string, because the same cards repeat in every snapshot.
- **Helpers:** the frontend reads card strings only through `cardName(card)` and `cardText(card)`. They fall back from `zh-TW` to `zh-CN` to `en`, and from `en` to `zh-CN`, so a card missing one field still shows something.
- **Known limitation:** converted text is not Blizzard's official Taiwan localization. Some card names differ from the official zhTW names. A later step can import official zhTW strings by DBF ID, the way artwork is pinned in `demo-art.json`. It would replace `name_tw` and `text_tw` where present and keep the conversion as the fallback. That needs a choice of data source.

## Logic that reads card text

- **Keyword marks:** Deathrattle is detected from the English `text`, so it does not depend on the locale.
- **Choose One modes:** parsed from the displayed text, with one pattern per language:
  - `en`: `Choose One - A; or B.`
  - `zh-CN`: `抉择：A；或者B。`
  - `zh-TW`: `抉擇：A；或者B。`

  The shared lead-in rule applies to each language: when the second mode starts with a number, it reuses the first mode's verb phrase. For example, "Give a minion +3/+1; or +1/+3" shows the second mode as "Give a minion +1/+3". If a text does not match, the panel falls back to the plain card text.
- **Tribe names:** come from the catalog, keyed by the engine race code.

## Text in the 3D scene

- **Card faces:** they draw only a few strings: the spell label and, without artwork, the first glyph of the name. The face cache key includes those strings, so switching language redraws the faces.
- **Combat labels:** they are DOM overlays and read the catalog when shown.

## Fonts

- `zh-CN`: PingFang SC, Microsoft YaHei.
- `zh-TW`: PingFang TC, Microsoft JhengHei.
- `en`: the system sans-serif stack.

CSS selects the stack with `:lang()`. The canvas face drawing uses the same stack through a shared `fontStack()` helper. Numbers keep Georgia in every locale.

## Layout

English strings are often longer than Chinese, so:

- HUD buttons size to their text.
- Tooltips keep their fixed width and wrap.
- The choice panel already wraps option text.

Each phase is checked in all three locales at the default window size.

## Scenarios

The menu shows scenario names from the catalog, keyed by scenario ID. The backend keeps its Chinese `instructions` as developer notes for the API docs.

## Testing

- **Catalog parity:** the types reject missing keys. A unit test also calls every message function with sample values and checks that each locale returns a non-empty string.
- **Locale resolution:** query, stored choice, browser languages, and a store that throws.
- **Card helpers:** the right field for each locale, plus the fallbacks.
- **Choose One parsing:** English and both Chinese patterns.
- **Backend:** card objects carry `name_tw` and `text_tw`, and a known phrase converts to Taiwan wording.

## Rollout

1. Locale core, catalogs, language menu, `<html lang>` and fonts.
2. Move every HUD, board, combat and accessibility string into the catalogs.
3. Card names and text: backend zhTW conversion, the frontend helpers, Choose One parsing and tribe names.
4. Optional: import official zhTW card strings.
